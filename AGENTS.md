# Website Guidelines

## Notes

- Write concise technical notes centered on algorithms, mathematical structure, design choices, experimental evidence, and derived insights.
- Organize the material by its conceptual logic rather than by the chronology of implementation. At section boundaries, establish the purpose and outcome at a high level before introducing formalism or detail; do not use an overview as a compressed narration of procedure. Treat code and repository organization as supporting context, not the main subject.
- Explain implementations through the algorithmic ideas and design decisions they embody rather than by translating code execution into prose. Include implementation details or small code excerpts only when they reveal a meaningful mechanism, trade-off, behavior, or boundary condition.
- Choose the representation that makes an idea clearest. Use mathematical notation when it exposes structure or relationships more directly than prose, without formalizing material that is clearer in ordinary language. Apply the same judgment to examples, lists, tables, code blocks, callouts, and diagrams instead of following a fixed template.
- Preserve the author's voice and use a level of formality proportional to the subject. Present local notation and implementation conventions as local conveniences, not universal concepts.
- Present experiments through the question, relevant evidence, and interpretation. Do not present expectations as observations or use placeholders for unfinished results.
- Preserve the existing problem, question, and answer structure where it helps connect assignment prompts to their solutions. Remove repetition and routine details that do not contribute to understanding.
- Preserve deliberate supplementary material such as paper references, representative applications, figures, screenshots, and interpretive callouts. Improve how this material is integrated, but do not remove it merely to shorten the notes.
- Treat the rendered page as the authority for formatting. After editing, inspect the generated output—especially mathematics, nested callouts, tables, figures, and code blocks—and revise markup that is valid in source form but renders incorrectly on the site.

Keep these principles broad and stable. Resolve isolated writing and rendering issues locally; revise this file only when a principle generalizes across the site.
