## Training a BPE Tokenizer

The whole training process of a BPE tokenizer can be split into 3 stages:

1. **Vocabulary initialization**: The initial vocabulary is 256 bytes. We will use a `dict[int, bytes]` ($\text{token id} \rightarrow \text{token}$) vocabulary.

2. **Pre-tokenization**: to count byte pairs, we need to first split the _document_ into _words_, which can be done with regular expressions. In this assignment, we will use [`r"""'(?:[sdmt]|ll|ve|re)| ?\p{L}++| ?\p{N}++| ?[^\s\p{L}\p{N}]++|\s++$|\s+(?!\S)|\s"""`](https://github.com/openai/tiktoken/blob/main/tiktoken_ext/openai_public.py#L13) from GPT-2 {% cite radford2019gpt2 %}. Here is an example:

    ```python
    import regex  # pip install regex (not re)
    tokens = regex.findall(
        pattern=r"""'(?:[sdmt]|ll|ve|re)| ?\p{L}++| ?\p{N}++| ?[^\s\p{L}\p{N}]++|\s++$|\s+(?!\S)|\s""",
        string="Hello world! I'm testing the tokenizer. It has 42 examples.",
    )
    print(tokens)
    # ['Hello', ' world', '!', ' I', "'m", ' testing', ' the', ' tokenizer', '.', ' It', ' has', ' 42', ' examples', '.']
    ```

3. **Compute BPE merges**: now we have all data needed to build the vocabulary. It is an iterative process and it will continue until certain stopping criterion is met, _e.g._ the vocabulary size has reached a given number. We can devide it into 2 steps:

    1. **Count token-pairs**: in each _word_, we need to findout the frequency of each token pair.
    For example:
        ```python
        def pair_count(word: str) -> dict[str, int]:
            pairs = {}
            for i in range(len(word) - 1):
                pair = word[i:i+2]
                pairs[pair] = pairs.get(pair, 0) + 1
            return pairs

        print(pair_count("chinchilla"))
        # {'ch': 2, 'hi': 2, 'in': 1, 'nc': 1, 'il': 1, 'll': 1, 'la': 1}
        ```
    2. **Merge**: the most frequent _token_ pair will be merged. If there is a tie, then take the lexicographically greater pair. In the previous example, we will merge token `b'h'`, `b'i'` and get a new token `b'hi'`, so this token is then added to the vocabulary.

> Here I will clarify some of the terminologies for easier code implementation and better consistency:
>
> - _document_(`list[word]`): the biggest unit of training data that consists of arbitrary text of arbitrary length.
> - _word_(`list[token]`): elements of _document_ split by a particular method. Here our _words_ are produced by the gpt-2 regex pattern split.
> - _token_(`bytes`): the smallest unit that the model reads. Initially, 1 token = 1 byte, but BPE will merge the most frequent token pairs into one token iteratively, so finally 1 token = n byte.

> - **Initial boundaries:** Divide the file into `desired_num_chunks` segments, _e.g._ for 1000 bytes and 4 chunks → [0, 250, 500, 750, 1000].

> - **Clean up:** Sort and deduplicate the boundary list.

### Initialization

Let's start with its initialization:

```python
class BPETrainer:
    def __init__(
        self,
        input_path: str | os.PathLike,
        vocab_size: int,
        special_tokens: list[str],
        **kwargs,
    ) -> None:

        self.input_path = input_path
        self.vocab = {i: bytes([i]) for i in range(256)}
        self.merges = []
        self.vocab_size = vocab_size
        self.special_tokens = sorted(special_tokens, key=len, reverse=True)
        self.special_tokens_pattern = re.compile("|".join(re.escape(t) for t in self.special_tokens))
        for tok in self.special_tokens:
            self.add_token(tok.encode("utf-8"))

        # used for getting boundaries
        self.desired_num_chunks = kwargs.pop("desired_num_chunks", 1024)
```

Here are some details that are worth mentioning:

1. `self.vocab`: the final vocabulary dict that we want to build. The key is token id and the value is the corresponding token. Notice that here we should use `bytes([i])`, **the square brackets are necessary**. `bytes(i)` is an all zero byte object of length i, _e.g._:
    ```shell
    >>> bytes(5)
    b'\x00\x00\x00\x00\x00'
    >>> bytes([5])
    b'\x05'
    ```

2. `self.vocab_size`: this is the target vocab_size, _i.e._, after training the BPE tokenizer, its vocabulary size will become `self.vocab_size` (including the _special tokens_). So in total there will be `self.vocab_size - 256 - #special_tokens` merges.

3. `self.special_tokens`: we need to split documents by special tokens in the first place. Here I sort it in descending order for the edge case:`["<|endoftext|><|endoftext|>", "<|endoftext|>"]`. If the document is first split by `<|endoftext|>`, then `<|endoftext|><|endoftext|>` in that document will be split into two tokens, which is not what we want.

### Pretokenization

In this pretokenization task, we can use multiprocessing library to speed up.

The basic task consists of 4 steps:

1. Load text;

2. Tokenize by special tokens;

3. Tokenize by regular expression;

4. Return counted words.

This part is quite clear and straightforward.

```python
def _pretokenize_single(self, args: tuple) -> Counter[str, int]:
    input_path, start, end = args
    with open(input_path, "rb") as f:
        f.seek(start)
        chunk_bytes = f.read(end - start)
    text = chunk_bytes.decode("utf-8", errors="ignore")
    documents = self.special_tokens_pattern.split(text)
    local_counter = Counter()
    for document in documents:
        words = PRETOKENIZE_PATTERN.findall(document)
        local_counter.update(Counter(words))
    return local_counter

def pretokenize(self, max_workers: int | None = None) -> Counter[str, int]:
    if max_workers is None:
        max_workers = os.cpu_count() or 1
    boundaries = self._get_boundaries(self.input_path, self.desired_num_chunks)
    task_args_list = [(self.input_path, boundaries[i], boundaries[i + 1]) for i in range(len(boundaries) - 1)]
    word_counter = Counter()

    with ProcessPoolExecutor(max_workers=max_workers, mp_context=multiprocessing.get_context("spawn")) as executor:
        futures = {executor.submit(self._pretokenize_single, task_args): task_args for task_args in task_args_list}
        for future in tqdm(as_completed(futures), total=len(futures), desc="Pretokenizing"):
            word_counter.update(future.result())

    return word_counter
```

The word counter is used as a coefficient for efficient token pair count calculation.

### Compute Merges

At each merge step we need to (1) select the most frequent pair and (2) update all related state. These structures support that:

1. **`word_counter: Counter[str]`** — How often each pre-token appears in the corpus. Built once during pretokenization; not changed during training. Counts are corpus frequencies (word occurrences, not unique types).

2. **`word_tokens: dict[str, tuple[bytes, ...]]`** — Token sequence for each word. Updated whenever that word is affected by a merge. Avoids rescanning the corpus during merges.

3. **`pair_counter: Counter[tuple[bytes, bytes]]`** — How often each adjacent token pair appears in the corpus. For a word that appears `c` times, each of its pairs contributes `c` to the total.

4. **`pair_words: defaultdict[tuple[bytes, bytes], set[str]]`** — For each pair, the set of words that contain it. Lets us quickly find all words that change when a pair is merged.

5. **`count_pairs: defaultdict[int, set[tuple[bytes, bytes]]]`** — For each frequency, the set of pairs with that frequency. Lets us find max-frequency pairs quickly instead of scanning all pairs.

**Merge loop:**
- Pick the merge pair: among pairs with the largest count, choose the lexicographically greater pair (tuple comparison).
- Collect all words that contain that pair via `pair_words`.
- For each such word:
  - Apply the merge to its token sequence (replace each occurrence of the pair with the merged token).
  - Compute the effect on pair counts: the merged pair is removed; the previous–merged and merged–next pairs are added; the old previous–first and second–next pairs are removed.
- Apply these changes to `pair_counter`, `count_pairs`, and `pair_words`.
- If any count bucket becomes empty, recompute the new maximum count.

**Time complexity**

| Phase | Complexity |
|-------|------------|
| Build `word_counter`, `word_tokens` | O(C) over corpus size C |
| Build `pair_counter`, `pair_words` | O(W · L) over W unique words, avg length L |
| Build `count_pairs` | O(P) over P distinct pairs |
| Merge: select merge pair | O(1) |
| Merge: apply merge to affected words | O(K · L) for K affected words |
| Merge: update pair stats + `max_count` | O(D) for D pair deltas; recompute `max_count` only when the max bucket empties, O(B) with B distinct count buckets |
| **Total over M merges** | O(C + W·L + P + M · (K·L + D + B)) |

For more details, you can refer to the `BPETrainer` class implementation.
I trained the BPE tokenizer on my Macbook M4 with the given datasets and vocabulary size = 32000 and it did not take too long:

## Saving a BPE Tokenizer

After training the tokenizer, the next step is to save it to disk. The two primary components to serialize are the **vocabulary** and the list of **merge operations**. While the handout does not specify an exact format, it is important to consider how to serialize these items robustly.

A key challenge is encoding bytes that are not visually distinguishable, such as invisible or whitespace characters. For example, if a space character (`' '`) is used as the token separator in the merge file, storing an actual space token becomes ambiguous. To address this, we should map invisible or ambiguous bytes to clearly visible representations, ensuring each token can be accurately and unambiguously saved and loaded.

Below is [the code](https://github.com/openai/gpt-2/blob/master/src/encoder.py#L9) used in gpt-2. It provides a reversible mapping from bytes to visible unicode characters, avoiding ambiguous whitespace and control codes:

```python
# https://github.com/openai/gpt-2/blob/master/src/encoder.py#L9
@lru_cache
def bytes_to_unicode():
    """
    Returns list of utf-8 byte and a corresponding list of unicode strings.
    The reversible bpe codes work on unicode strings.
    This means you need a large # of unicode characters in your vocab if you want to avoid UNKs.
    When you're at something like a 10B token dataset you end up needing around 5K for decent coverage.
    This is a signficant percentage of your normal, say, 32K bpe vocab.
    To avoid that, we want lookup tables between utf-8 bytes and unicode strings.
    And avoids mapping to whitespace/control characters the bpe code barfs on.
    """
    bs = list(range(ord("!"), ord("~") + 1)) + list(range(ord("¡"), ord("¬") + 1)) + list(range(ord("®"), ord("ÿ") + 1))
    cs = bs[:]
    n = 0
    for b in range(2**8):
        if b not in bs:
            bs.append(b)
            cs.append(2**8 + n)
            n += 1
    cs = [chr(n) for n in cs]
    return dict(zip(bs, cs))
```

For example, the unicode for `' '` is 32, and when saved to file, it will be something like:

```shell
>>> d = bytes_to_unicode()
>>> d[32]
'Ġ'
```

Also, this process is reversible so we can correctly recover the original information from the given files.

Notice that the class attribute `vocab` is $\text{token id} \rightarrow \text{token}$, but when saved to disk, we use a $\text{token} \rightarrow \text{token id}$ mapping, so the key and the value are swapped when saving:

```python
def bytes_to_gpt2_str(b: bytes) -> str:
    """Convert bytes to GPT-2 token string representation."""
    byte_encoder = bytes_to_unicode()
    return "".join(byte_encoder[byte_val] for byte_val in b)

gpt2_vocab = {
    # use gpt2 vocab
    bytes_to_gpt2_str(token_bytes): tid
    for tid, token_bytes in self.vocab.items()
}
vocab_path = os.path.join(output_path, "vocab.json")
with open(vocab_path, "w", encoding="utf-8") as f:
    json.dump(gpt2_vocab, f, ensure_ascii=False)
```

After training and saving a tokenizer, we are ready to use it.

```python
class BPETokenizer:

        vocab: dict[int, bytes]

    def from_files(cls, vocab_filepath, merges_filepath, special_tokens=None):
        """
        Class method that constructs and return a Tokenizer from a serialized vocabulary and list of merges (in the same format that your BPE training code output) and (optionally) a list of special tokens. This method should accept the following additional parameters:
        vocab_filepath: str
        merges_filepath: str
        special_tokens: list[str] | None = None
        """

    def encode(self, text: str) -> list[int]:
        """Encode an input text into a sequence of token IDs."""

    def encode_iterable(self, iterable: Iterable[str]) -> Iterator[int]:
        """
        Given an iterable of strings (e.g., a Python file handle), return a generator that lazily yields token IDs. This is required for memory-eﬀicient tokenization of large files that we cannot directly load into memory.
        """

    def decode(self, ids: list[int]) -> str:
        """Decode a sequence of token IDs into text."""
```

For the `from_files` method, pay close attention to the vocabulary’s key-value structure:

```python
with open(vocab_filepath, encoding="utf-8") as f:
    gpt2_vocab = json.load(f)
vocab = {
    int(token_id): gpt2_str_to_bytes(stoken)
    for stoken, token_id in gpt2_vocab.items()
}
```
Here, each key in the new vocabulary is the integer token ID (`int(token_id)`) and each value is the corresponding byte sequence (`gpt2_str_to_bytes(stoken)`).

For the `encode` method, consider the following steps:

1. **Split by special tokens:** Segment the input text into chunks separated by special tokens. Special tokens must remain intact and be reserved.

2. **Extract words from each segment:** Use regular expressions to split non-special segments into words. Ignore empty tokens and treat special tokens as atomic units.

3. **Tokenize each word:** For each word:
    - Represent the word as a list of single-byte elements.
    - Repeatedly merge byte pairs according to the tokenizer’s merge rules, one merge per iteration.
    - Always merge the pair with the lowest rank; in case of ties, merge the leftmost pair first.
    - After a merge, rebuild the word as a sequence of merged tokens.
    - Use `lru_cache` to cache tokenization results and improve efficiency.

# Transformer

The Transformer language model consists of a token embedding layer, a stack of identical Transformer blocks, a final normalization layer, and a linear projection followed by softmax to produce output probabilities. Each Transformer block uses a **pre-norm** layout {% cite xiong2020layer %}: normalization is applied before each sub-layer (self-attention and feed-forward), and residual connections add the sub-layer input to its output, which stabilizes training for deep models.

## Model Overview

<figure style="max-width: 480px; margin: 0 auto 1rem;">
  <img src="{{ '/assets/img/transformer.png' | relative_url }}" alt="Overview of the Transformer language model" style="width: 100%;">
  <figcaption class="caption">Figure 1: An overview of the Transformer language model.</figcaption>
</figure>

The Transformer language model begins by mapping input tokens to continuous representations using an embedding layer. These embeddings are then sequentially processed through a stack of `num_layers` identical Transformer blocks. After traversing all blocks, the output undergoes a final normalization step. Finally, a linear projection maps the representations to logits over the vocabulary, and a softmax operation produces probabilities for next-token prediction.

Each Transformer block contains two main sub-layers: a causal multi-head self-attention mechanism (with Rotary Position Embeddings, or RoPE) and a position-wise feed-forward network. Both sub-layers utilize a pre-normalization strategy and residual connections:

<figure id="fig-prenorm-block" style="max-width: 480px; margin: 0 auto 1rem;">
  <img src="{{ '/assets/img/transformer-block.png' | relative_url }}" alt="Pre-norm Transformer block" style="width: 100%;">
  <figcaption class="caption">Figure 2: A pre-norm Transformer block.</figcaption>
</figure>

In the pre-norm design {% cite xiong2020layer %}, normalization is applied before each sub-layer's operation. The residual connections (indicated by dotted arrows) ensure that the original input to each sub-layer is added back, allowing gradients to propagate effectively through the depth of the network. This architecture improves training stability and helps deep models converge more reliably.

For parameter initialization, we will use:

* **Linear weights**: $\mathcal{N}\left(\mu=0,\, \sigma^2=\frac{2}{d_{in} + d_{out}}\right)$ truncated at $[-3\sigma, 3\sigma]$.
* **Embedding**: $\mathcal{N}(\mu=0,\, \sigma^2=1)$ truncated at $[-3, 3]$.
* **RMSNorm**: $1$

Use `torch.nn.init.trunc_normal_` to initialize weights with a truncated normal distribution as specified above.

## Linear Module

A linear (fully-connected) layer performs:

$$
y = Wx + b, \quad\text{where } W \in \mathbb{R}^{d_\text{out} \times d_\text{in}},\ x \in \mathbb{R}^{d_\text{in}},\ b \in \mathbb{R}^{d_\text{out}}
$$

Note that we **do not include a bias term**, following most modern LLMs.

- **Input shape:** $(\ldots, d_\text{in})$
- **Output shape:** $(\ldots, d_\text{out})$

```python
class Linear(nn.Module):
    def __init__(
        self,
        in_features: int,
        out_features: int,
        device: torch.device | None = None,
        dtype: torch.dtype | None = None,
        weights: torch.Tensor | None = None,
    ):
        super().__init__()
        self.in_features = in_features
        self.out_features = out_features
        if weights is not None:
            # If a weight matrix is provided, use it
            self.weights: nn.Parameter = nn.Parameter(weights)
        else:
            # Otherwise, initialize as normal
            self.weights: nn.Parameter = nn.Parameter(
                torch.empty((out_features, in_features), device=device, dtype=dtype)
            )
            self.reset_parameters()

    def reset_parameters(self):
        # Linear weights: N(0, 2/(d_in + d_out)), truncated at [-3 sigma, 3 sigma]
        std = (2 / (self.in_features + self.out_features)) ** 0.5
        torch.nn.init.trunc_normal_(self.weights, mean=0.0, std=std, a=-3 * std, b=3 * std)

    def forward(
        self,
        x: Float[torch.Tensor, "... in_features"],
    ) -> Float[torch.Tensor, "... out_features"]:
        # einsum: "... i, o i -> ... o"
        out: Float[torch.Tensor, "... out_features"] = einsum(x, self.weights, "... i, o i -> ... o")
        return out
```

## Embedding Module

An embedding layer transforms integer token IDs into continuous vector representations.

- **Input shape:** $(\ldots,)$ (arbitrary batch shape of integer token IDs)
- **Output shape:** $(\ldots, d_\text{embedding})$ (same batch shape, with each ID replaced by a $d_\text{embedding}$-dimensional vector)


This operation is typically implemented as a simple lookup into a learnable parameter matrix $E \in \mathbb{R}^{\|\text{vocab}\| \times d_\text{embedding}}$
, where each row corresponds to one token in the vocabulary. For each input token ID $i$, the output is $E[i]$.

```python
class Embedding(nn.Module):
    def __init__(
        self,
        num_embeddings: int,
        embedding_dim: int,
        device: torch.device | None = None,
        dtype: torch.dtype | None = None,
        weights: torch.Tensor | None = None,
    ):
        super().__init__()
        self.num_embeddings = num_embeddings
        self.embedding_dim = embedding_dim
        if weights is not None:
            self.weights = nn.Parameter(weights)
        else:
            self.weights = nn.Parameter(torch.empty((num_embeddings, embedding_dim), device=device, dtype=dtype))
            self.reset_parameters()

    def reset_parameters(self):
        # Embedding weights: N(0, 2/(num_embeddings + embedding_dim)), truncated at [-3 sigma, 3 sigma]
        std = (2 / (self.num_embeddings + self.embedding_dim)) ** 0.5
        torch.nn.init.trunc_normal_(self.weights, mean=0.0, std=std, a=-3 * std, b=3 * std)

    def forward(
        self,
        x: Int[torch.Tensor, "..."],
    ) -> Float[torch.Tensor, "... embedding_dim"]:
        return self.weights[x]
```

## Pre-norm Transformer Block

A **pre-norm Transformer block** is a fundamental unit in modern Transformer architectures. In this design, layer normalization is applied *before* each core sublayer—specifically before both the Multi-Head Self-Attention (MHSA) and the Feed-Forward Network (FFN). After each sublayer, its output is added back to the original input via a residual (skip) connection. This structure, illustrated in [Figure 2](#fig-prenorm-block) (the pre-norm Transformer block diagram) and described in {% cite vaswani2017attention %} (original Transformer), {% cite nguyen2019transformers %} (PreNorm), and {% cite xiong2020layer %} (Pre-LN vs Post-LN analysis), improves gradient flow and stabilizes training, particularly for deep networks.

Conceptually, each pre-norm Transformer block can be summarized as:
- **Input $\to$ LayerNorm $\to$ MHSA $\to$ Add Residual $\to$ LayerNorm $\to$ FFN $\to$ Add Residual**
- Each branch follows: $x' = x + \mathrm{Sublayer}(\mathrm{LayerNorm}(x))$

This approach leads to smoother gradient propagation and is recommended for stable optimization in deep Transformer models {% cite xiong2020layer %}.

### RMS Layer Norm

RMSNorm normalizes each input vector by its root mean square (RMS) instead of mean and variance. For vector $a \in \mathbb{R}^{d_\text{model}}$:

$$
\text{RMSNorm}(a)_i = \frac{a_i}{\sqrt{\frac{1}{d_\text{model}}\sum_{i=1}^{d_\text{model}} a_i^2 + \epsilon}} \cdot g_i
$$

where $g_i$ is a learnable parameter and $\epsilon$ is a small constant for stability. RMSNorm is computationally simpler than standard LayerNorm and often performs similarly. When implementing, upcast to `float32` before computing RMS for stability.

```python
class RMSNorm(nn.Module):
    def __init__(
        self,
        d_model: int,
        eps: float = 1e-5,
        device: torch.device | None = None,
        dtype: torch.dtype | None = None,
        weights: torch.Tensor | None = None,
    ):
        super().__init__()
        self.d_model = d_model
        self.eps = eps

        if weights is not None:
            self.g = nn.Parameter(weights)
        else:
            self.g = nn.Parameter(torch.ones(d_model, device=device, dtype=dtype))

    def forward(
        self,
        x: Float[torch.Tensor, "... d_model"],
    ) -> Float[torch.Tensor, "... d_model"]:
        orig_dtype = x.dtype
        x = x.to(torch.float32)

        # Compute root mean square along the last dimension
        rms = torch.sqrt(torch.mean(x**2, dim=-1, keepdim=True) + self.eps)
        x_normed = x / rms

        # Apply the learned scaling parameter (self.g)
        out = x_normed * self.g

        return out.to(orig_dtype)
```

### Position-Wise Feed-Forward Network

Modern LLMs use the **SwiGLU** activation in their feed-forward networks, which combines SiLU (Swish) and a gating mechanism:

$$
\text{FFN}(x) = \text{SwiGLU}(x) = [\, \mathrm{SiLU}(x W_1) \odot (x W_3) \,] W_2
$$

where $\mathrm{SiLU}(x) = x \cdot \sigma(x)$, $W_1,W_3 \in \mathbb{R}^{d_\text{model} \times d_\text{ff}}$, $W_2 \in \mathbb{R}^{d_\text{ff} \times d_\text{model}}$, and $\odot$ is element-wise multiplication. No bias is used.

```python
class SiLU(nn.Module):
    def __init__(self):
        super().__init__()

    def forward(
        self,
        x: Float[torch.Tensor, "... d_model"],
    ):
        return x / (1 + torch.exp(-x))


class SwiGLU(nn.Module):
    def __init__(
        self,
        d_model: int,
        d_ff: int,
        device: torch.device | None = None,
        dtype: torch.dtype | None = None,
        weights1: Float[torch.Tensor, "d_ff d_model"] | None = None,
        weights2: Float[torch.Tensor, "d_model d_ff"] | None = None,
        weights3: Float[torch.Tensor, "d_ff d_model"] | None = None,
    ):
        super().__init__()
        self.d_model = d_model
        self.d_ff = d_ff
        self.silu = SiLU()
        self.weights1 = Linear(in_features=d_model, out_features=d_ff, weights=weights1)
        self.weights2 = Linear(in_features=d_ff, out_features=d_model, weights=weights2)
        self.weights3 = Linear(in_features=d_model, out_features=d_ff, weights=weights3)

    def forward(self, x: Float[torch.Tensor, "... d_model"]) -> Float[torch.Tensor, "... d_model"]:
        activations = self.silu(self.weights1(x))
        gates = self.weights3(x)
        return self.weights2(activations * gates)
```
